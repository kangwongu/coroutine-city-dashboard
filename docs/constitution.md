# Project Constitution

## 목적

- 코틀린 코루틴의 구조적 동시성(`coroutineScope`, `async`/`awaitAll`)을 실제 네트워크 I/O가 섞인 코드에서 직접 써보고 체감한다.
- 순차 호출과 병렬 호출의 응답 속도 차이를 감이 아니라 숫자로 확인한다.
- `coroutineScope`(fail-fast)와 `supervisorScope`(partial-success)의 예외 전파 차이를 실제 API 실패 상황에서 경험한다.
- 작은 MVP로 시작해서 실무에서 흔한 패턴(부분 실패 처리, 의존관계 있는 호출 체이닝, 블로킹 클라이언트 비교, 캐싱/재시도)까지 단계적으로 확장하며 배우는 재미를 느낀다.

## 성공 기준

- 동일한 기능을 제공하는 순차/병렬 엔드포인트가 각각 정상 동작하고, 응답의 `timingMs`로 두 방식의 속도 차이가 명확히 드러난다.
- 4개 외부 API(날씨, 국가 정보, 공휴일, 환율) 연동이 실제로 성공한다.
- `coroutineScope`와 `supervisorScope` 두 방식을 모두 구현해, 하나의 API가 실패했을 때 동작 차이(전체 실패 vs 부분 성공)를 직접 확인한다.
- 완전 독립 병렬 구조에서 시작해, 외부 API 응답값으로 다른 외부 API를 호출하는 의존관계 구조까지 실제로 리팩터링해본다.

## 제약사항

- **배포하지 않는다.** 로컬 환경에서 실행하고 체감하는 것이 목표이며, 인프라/배포 설정은 범위 밖이다.
- **점진적으로 개발한다.** 처음에는 4개 API를 서로 의존관계 없이 완전히 병렬로 호출하는 구조로 시작하고, 이후 단계에서 한 API의 응답값(예: 국가코드, 통화코드)을 다른 API 호출의 입력으로 쓰는 의존적 호출 구조로 리팩터링한다. 단순한 fan-out/fan-in부터 순차와 병렬이 섞인 구조까지 단계적으로 경험하는 것이 의도다.
- Spring Boot 4.x + Kotlin + JDK 21, Spring MVC 기반으로 만든다. WebFlux/Reactor 타입은 컨트롤러/서비스 레벨에 노출하지 않고 `suspend fun` 위주로 작성한다.
- HTTP 클라이언트는 MVP 기준 WebClient(논블로킹)를 사용한다. 블로킹 클라이언트(RestTemplate) 비교는 별도 확장 단계에서만 다룬다.
- 무료로 사용할 수 있는 외부 API만 사용하고, API 키가 필요한 연동은 최소화한다.
- 초기 단계는 자동화 테스트 없이 실제 API를 직접 호출해 수동으로 검증한다. 자동화 테스트(WireMock 등)는 이후 단계에서 추가한다.
- 캐싱, 재시도, 타임아웃, 서킷브레이커 등 실무적 기능은 초기 범위에서 제외하고, 이후 단계적으로 추가한다.
